# Tools exempt from behavior-fixture coverage, one per line with a reason.
# Exemption is for tools the behavior runner structurally cannot pin: they
# make no HTTP request (nothing to capture) and their outputs are either
# language/environment-specific by design or stateful local data. Their
# cross-language contract is enforced elsewhere: input schemas by the
# input-proto/tool-parity gates, output SHAPE by the meta-proto gate and the
# conformance corpus. Adding a tool here requires a reason; prefer a fixture
# whenever the tool makes an HTTP call or has shareable local validation.
# Format: <tool>\t<reason>
# NEW entries must also carry the baseline-guard acceptance annotation
# (append: `  # accepted YYYY-MM-DD <reason or tracking-issue URL>`). The
# guard diffs this file the same way it diffs the ratchets, because an
# exemption is permanent coverage loss and deserves a dated commitment;
# verify_behavior reads only the tab-split tool name, so the annotation
# never changes what the gate exempts.
# REMOVING an entry needs no annotation: it hands coverage back, which is the
# direction this file is supposed to move. Drop the line in the same change
# that lands the tool's fixture, since verify_behavior fails an exempt tool
# that has one (an exemption over a fixture would mask the fixture).
# The list is empty today: every tool in the manifest carries a fixture.
